features

Everything about a port, in one place.

Port, PID, process, container, user, uptime and what the port is usually for, all in a live table.

🔎

See every port

A live table of every listening port with PID, name, user, uptime and bind address. Refreshes every 2 s.

🐳

Docker-aware

Shows which container owns a port (docker: kafka-1), not just docker-proxy or com.docker.backend.

⌨️

One-key free

Select a row and press K. Containers get docker stop; processes are asked to exit politely first.

🎯

Ask about one port

portpilot 9092 answers "who is on 9092?" with the full command line and the container image.

🛡️

Safe by default

Always asks first, and refuses to touch system processes like svchost.exe, launchd or sshd.

🧩

Script-friendly

--json output, and exit codes that answer "is this port busy?": portpilot 5432 || docker compose up -d

install & use

Up and running in 10 seconds.

Works in PowerShell, Windows Terminal, macOS Terminal and any Linux shell.

pip install portpilot-cliinstall from PyPI (the command is still portpilot)
portpilotlive table of every listening port
portpilot 9092who is using port 9092?
portpilot kill 9092free port 9092 (asks first)
portpilot --dockeronly ports owned by Docker containers
portpilot --jsonmachine-readable output for scripts

Keys in the live view

↑ ↓select a row
Kfree the selected port (asks y/N)
Dtoggle Docker only
/filter by port, name or container
Rrefresh now
Qquit

Tip: on macOS and Linux run sudo portpilot to see other users' processes; on Windows, an Administrator terminal shows system services.

how it works

Small, honest and careful.

psutil: listening sockets→port → PID → process
docker ps: published ports→port → container
Rich table→ K →docker stoporterminate process

No daemon, no background service, no telemetry. It reads the OS socket table, asks Docker, draws a table and exits.

  • Asks before stopping anything (unless you pass -y).
  • Never touches core OS processes such as PID 0/1/4, System, lsass.exe, launchd, systemd and sshd.
  • Polite first: terminate, then force-kill only if the process ignores it for 3 s.
  • PID-reuse guard: re-checks the process start time right before acting.
